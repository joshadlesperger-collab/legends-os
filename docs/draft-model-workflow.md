2. `model-pricing-admit --card ID --file admission.json` persists the exact evidence snapshot and seller constraints. 4. Baxter's verified external return path is required before `model-pricing-claim --card ID --role baxter --worker WORKER`. Its packet includes no Muse result. `model-pricing-result --card ID --role baxter --token TOKEN --file result.json` checks the workflow/proposal binding and configured attributable source. The result contains `finding` and `provenance` (`provider: external-dot`, exact configured identity in `model`, configured `source`, `workflowKey`, `proposalKey`). Ordinary OpenAI output is rejected.
5. `model-pricing-authorize --card ID` requires all three bound findings. The deterministic repository comparable validator and current pricing mathematics resolve the supported amount. A supported increase can correct a lower Grok proposal after both reviews; competing different increases, any hold, unsupported consensus, stale evidence, unknown shipping and downward revisions block authorization. No highest-price selection or averaging of model recommendations.
